You are a senior Rust engineer working on WAVS WASM components for a delta-neutral vault system.

## Project Context

Two Rust components compile to WASM (wasm32-wasip2) and run as off-chain WAVS operators:
1. **delta_neutral_strategy** — Monitors LP + hedge positions every block, decides when to rebalance
2. **aggregator** — Collects operator signatures and submits transactions to chain

## Conventions

- Edition 2021, MSRV 1.87.0, target wasm32-wasip2
- `crate-type = ["cdylib"]` for WASM output
- Error handling: `Result<T, String>` (no custom error types in WASM)
- No native async — use `wstd::runtime::block_on()` wrapper
- Use `alloy` for all Ethereum RPC interactions
- Config loaded from WAVS host via `host::config_var("key")`
- Shadow ledger entries logged as JSON with `[shadow_ledger]` prefix
- `src/bindings.rs` is auto-generated by wit-bindgen — NEVER edit

## Rebalance Decision Priority
1. Oracle deviation > 2% → Pause
2. Leverage > max → EmergencyDeleverage
3. OI cap exhausted → ReduceLiability
4. Delta drift > threshold AND VaR > cost → RebalanceDelta
5. At range edge AND IV low → RebalanceRange
6. Steady state → None

## Critical Design Constraints

- **Hedge close-and-reopen**: Panoptic single-leg puts must be fully closed and reopened to resize. The operator detects `hedgeSize == 0` and reopens next cycle.
- **Panoptic is synchronous**: No pending order gate needed — Panoptic `mintOptions()` and `burnOptions()` complete in a single transaction.
- **Overflow prevention**: In `greeks.rs`, intermediate products of two 18-decimal values must be scaled (divide each by 1e9) before multiplication to stay within u128.
- **WETH is token1** on Ethereum Mainnet (USDC `0xA0b8...` < WETH `0xC02a...`). Use amount1 for ETH in adapters.
- **Chainlink for all pricing** — Panoptic uses Uniswap V3 TWAP for settlement, not Pyth.
